# 高二（2）班：最后一节课

> 17:30 以前，不要相信任何一次下课铃。

**版本：v2.0**

一款单文件 HTML 校园恐怖潜行游戏，结合第一人称课桌视角、Galgame 对话、课堂资源管理、限时反应和多结局探索。玩家需要度过六节课程，应对教师巡逻与后门检查，辨别真正的放学铃，并探索离开学校的不同方式。

全部游戏代码位于 `index.html`：HTML、CSS、JavaScript 内嵌，不依赖外部框架、CDN、图片、音频文件、数据库或业务后端。桌面浏览器为主要操作平台。

## 1. 快速开始

### 直接打开

将完整源码包解压到固定文件夹，用浏览器打开 `index.html`，选择“开始这一天”或“快速模式”。已有有效进度时，可在主菜单选择“继续上次游戏”。

游戏不需要安装运行依赖，也没有构建步骤。只运行游戏时不需要 `tests/` 目录。

**注意：直接打开本地 HTML 的存储行为取决于浏览器。** 移动文件、切换浏览器、使用无痕模式或清理站点数据，都可能导致原记录不可见或被删除。重要进度请通过游戏内“存档 → 导出备份”另存为 JSON 文件。

### 可选：通过固定本地地址运行

电脑已安装 Python 3 时，可在 `index.html` 所在目录执行：

```bash
python -m http.server 8000 --bind 127.0.0.1
```

然后在浏览器打开：

```text
http://127.0.0.1:8000/
```

这只是提供静态文件的可选方式，不会增加游戏后端或云存档。后续请使用同一地址和端口进入游戏；从直接打开文件切换到 HTTP 地址前，应先导出进度，再在新地址导入。

## 3. 操作说明

| 操作 | 键盘或界面入口 |
| --- | --- |
| 切换五种课堂行动 | `1` 听课、`2` 作业、`3` 魔方、`4` 手机、`5` 观察 |
| 收好物品 | 平时按 `Space`，收好物品并切回听课 |
| 紧急三步隐藏 | 危险提示出现后，连续按三次 `Space`，依次完成藏好、拿笔、看书；也可点击对应按钮 |

快捷键会随当前界面改变用途。例如，选择题中的数字键用于选答案，不会切换课堂行动。需要连续操作时应重复按下并松开按键，不能靠长按替代多次操作。

“不要动”等静止挑战期间，应停止鼠标、触摸和键盘操作，按提示等待；不要为了确认状态而连续点击。

### 全屏与画面设置

游戏使用浏览器 Fullscreen API。进入全屏后保持 16∶9 比例，窗口尺寸变化时等比例缩放；退出游戏全屏时自动暂停。

全屏请求被浏览器或嵌入容器拒绝时，会显示提示，仍可继续在窗口中游戏。部分桌面浏览器也可使用自身的 `F11` 全屏功能，具体取决于浏览器和系统。

对闪烁或震动敏感的玩家，可在“设置”中关闭“恐怖闪烁”和“屏幕震动”。文字、阴影和声音提示仍会保留。

## 4. 自动保存与网页中断续玩

### 保存时机

游戏进行时，每累计约 **5 秒有效游戏时间**自动记录一次，关键操作和剧情转场也会更新记录。页面切到后台、窗口失去焦点，以及 `pagehide`、`freeze` 事件触发时，会尝试立即保存并暂停。

记录包含课程与时间、资源属性、作业和魔方进度、手机状态、教师和后门状态、对话位置、事件队列、限时挑战剩余时间、隐藏步骤、随机选项、逃生路线与距离、冲刺进度，以及线索和同桌互动。

### 恢复步骤

1. 重新打开同一浏览器中的同一游戏页面。
2. 点击主菜单“继续上次游戏”。
3. 在恢复确认界面检查记录，再继续游戏。

读档恢复的是保存时的实际状态，不只是本节课开头。恢复确认期间不扣游戏时间；继续后有 **2 秒准备缓冲**，离线时间不计入游戏倒计时。

### 保存的边界

**自动保存不等于任何中断都零丢失。** 浏览器被强制结束、系统回收进程或突然断电时，页面离开事件可能不触发，只能恢复最近一次成功保存的记录。

浏览器拒绝存储或空间不足时，游戏会提示记录仅保留在当前页面内存中。此时仍可游玩和进行内存检查点重试，但关闭页面前必须导出 JSON 备份，否则无法依靠内存恢复。

## 5. Game Over 与检查点重试

**“当前自动记录”和“安全检查点”分别保存。** 自动记录用于继续中断的游戏；检查点用于失败后回到较早的可继续状态。失败或结局画面不会将已有游戏快照覆盖成失败画面。

Game Over 后，点击“从最近检查点重新出发”。**普通模式和快速模式均支持**，不必默认从第一节课重玩。

系统在课程开头、关键挑战、逃生路线和最终冲刺前等位置建立检查点，保留最近 **12 个**。课堂计时累计约 30 秒且满足安全条件时，也会建立安全课堂检查点。此外，单独保留本节开头、17:30 放学分歧和手动存档。

逃生距离过低时不会建立新的路线检查点，以减少濒临失败的状态覆盖较早记录的情况。检查点不保证接下来的操作一定成功。

回读记录会回退当前周目的任务、资源和线索，**但不会抹掉已经解锁的结局**。可以从结局页回到放学分歧尝试其他选择；没有收集的早期线索，仍需回到更早记录或在新周目补齐。

新开一天会先确认是否替换当前周目记录。需要保留原周目时，请先导出备份。

## 6. 备份、迁移与存档保护

### 手动备份与迁移

在游戏内打开“存档”，可进行手动保存、查看记录点、导出备份和导入备份。

迁移到另一台设备、另一款浏览器或另一个页面地址时：在原页面导出 JSON 文件，在新页面选择“存档 → 导入备份”，确认后再继续。覆盖升级或移动 HTML 文件前，也应先导出备份并保留旧文件。

**本项目没有账号系统或云存档，游戏不会上传记录。** 导出的 JSON 文件需要自行保管。

### 存储键

| `localStorage` 键 | 用途 |
| --- | --- |
| `last-class.progress.v2` | v2 进度主记录 |
| `last-class.progress.v2.backup` | 上一份有效进度备份 |
| `last-class.offline.v1` | 结局档案、最佳记录、设置、手机限制等兼容记录 |

存档采用带版本与校验值的 JSON。主记录损坏时，尝试读取有效备份；导入会检查格式、版本、长度、字段和校验值，并要求确认。**校验值用于发现意外损坏，不是加密或防作弊机制。**

另一标签页写入较新进度时，本页会停止自动覆盖并提示冲突。可先导出本页进度，再选择读取较新记录或明确接管写入。尽量避免同时在多个标签页游玩同一存档。

### 旧版兼容与清除记录

同一浏览器可访问的原存储位置中，v2 可读取旧版结局、最佳记录、设置和手机限制。**旧版没有保存中途进度，因此不能恢复升级前未保存的课堂进度。**

“清除本地存档”会同时删除进度、备份和结局／设置记录，操作不可撤销。该操作只能在主菜单或结局页进行；执行前请先导出备份。

## 9. 开发说明

### 技术结构

界面主要使用 HTML DOM 与 CSS，人物和场景采用程序化样式；音效由 Web Audio API 生成。游戏逻辑、剧情、题库、存档和响应式处理均位于同一个内嵌脚本中。

直接用 UTF-8 文本编辑器修改 `index.html` 即可，不需要打包工具。

| 修改目标 | 源码定位 |
| --- | --- |
| 课程时长、教师、课堂介绍 | `CLASSES` |
| 提问题库 | `QUESTIONS` |
| 结局名称、正文、提示与合法 ID | `ENDINGS`、`ENDING_IDS` |
| 调查目标与线索内容 | `EVIDENCE` |
| 课程固定事件 | `LESSON_EVENTS` |
| 剧情中断后的续接 | `CONTINUATIONS`、`dispatchContinuation` |
| 自动记录与进度读取 | `autoSave`、`loadProgress` |
| 检查点建立与快照恢复 | `rememberCheckpoint`、`restoreSnapshot` |
| 全屏与等比例缩放 | `toggleFullscreen`、`resize` |

新增结局时，应同步更新结局数据与合法 ID，并在游戏流程中接入实际触发条件，而不只是增加档案卡片。

修改剧情或挑战时，应同时检查其保存状态和恢复入口。尤其要验证对话中途、限时挑战中途、分歧选择前后能否读档续接。修改存档结构时，还应检查版本校验、导入导出和旧记录兼容性。

### 开发测试

测试依赖仅用于开发：Python 3.10+、Python Playwright 和 Chromium。**游戏本身不需要这些依赖。**

准备好依赖和 Chromium 后，在项目根目录执行：

```bash
python tests/test_game.py --chromium /usr/bin/chromium
```

将 Chromium 路径替换为本机实际可执行文件路径；路径包含空格时加引号。测试脚本会更新 `tests/results.json` 和界面截图。随包说明还要求修改后先进行 JavaScript 语法检查。

生产页面默认不暴露测试接口；测试脚本会在隔离文档中启用测试入口。

## 11. 常见问题

### 主菜单没有出现继续入口

检查是否使用了同一浏览器、同一页面地址或文件位置，是否处于无痕模式，或是否清理了浏览器数据。已有 JSON 备份时，可通过“存档 → 导入备份”恢复。旧版没有保存的中途进度无法通过升级补回。

### 保存提示失败，还能继续玩吗？

可以继续游玩，但记录可能只在当前页面内存中。关闭页面前先导出备份，不要把“当前页面还能重试”当作“下次打开也能恢复”。

### 失败后继续游戏仍接近失败怎么办？

自动记录偏向恢复中断现场。需要回到较早状态时，应使用“从最近检查点重新出发”，或在存档管理中选择更早的记录点。

### 手机按钮为什么不能使用？

“电子设备管理”结局会限制之后新周目的手机。限制生效前的检查点仍按当时的手机权限恢复；这属于结局效果，不是随机禁用。

### 全屏或声音没有生效怎么办？

先通过页面按钮进行交互，并检查声音按钮和设置中的音量。全屏受浏览器权限限制，被拒绝时可以继续窗口模式；浏览器可能要求用户交互后才允许启动音频。

### 修改源码后，旧存档还能使用吗？

不能对任意改动保证兼容。修改存档字段、剧情恢复标识或事件结构前，应保留原 HTML 和导出备份，修改后验证旧记录恢复。需要新存档格式时，应实现明确的版本迁移，而不是静默丢弃不兼容数据。
